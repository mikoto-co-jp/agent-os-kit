# 実行を帳簿へ書く — 便が走ったことを残す 1 手（全便の正本）

> **最初に `.claude/rules/` の 3 枚（規矩・メモリシステム・主君）を読む。**この便は棚のルート以外で起動されることがあり、その時は規矩が載っていない（暫定。cwd で起こせるようになったら消す）

便が走ったか・どう終わったかの正本は**記録 MCP `kiroku` の実行表**（`run_start`／`run_end`＝規矩 §4 の「便・席の 1 回の実行。手が要った率の分母」）。見る窓は `docs/SCOPE_PROGRESS.md` §5。中身の山は `11一時ファイル/`（7 日で消える）。**便のログの紙は持たない**（紙は腐る・数えられない）。

## 走り出しに 1 回

`run_start`

| 引数 | 何を渡すか |
|---|---|
| `seki` | **`scheduler` の 1 語**（下の ⛔ を読む） |
| `bin` | この便の名前（この箱の手順書のファイル名と同じ） |
| `tenantId` | 規矩 §3 の値 |

返ってくる `id` を控える。

## 終わりに 1 回

`run_end`

| 引数 | 何を渡すか |
|---|---|
| `seki` | `scheduler`（`run_start` と同じ） |
| `id` | 控えた実行 id |
| `kekka` | **`成功` / `失敗` / `手が要った` の 3 語だけ**（表に無い語は server が拒む） |
| `ledger_ids` | この便で `ledger_append` を撃っていたら、その行の id |

| 結果 | いつ選ぶか |
|---|---|
| `成功` | 手順を最後まで通した。**差分なしで終わったのも 成功**（走ったことに変わりはない） |
| `失敗` | 途中で止まった・門が落ちた・書くはずの物を書けなかった |
| `手が要った` | 人の手番が 1 回でも要った（合言葉・確認コード・GO・手で直した）。⚠️ これが無人化の測り（規矩 §5-6） |

## 中身の数字はどこへ

帳簿の 1 行には入らない。`11一時ファイル/便の実行-YYYY-MM.tsv` に 1 行（タブ区切り・無ければ作る）:

```
<開始 ISO>	<便の名前>	<結果>	<実行 id>	<中身>
```

`<中身>` は以前ログの末尾に書いていた `｜` 区切りの数字をそのまま。これが `docs/SCOPE_PROGRESS.md` §5 の「実行」の窓になる（7 日で消える＝窓は直近だけ。**正本は帳簿**）。

## ⛔ 守ること

- ⛔ **`seki` に `scheduler` 以外を書かない。**他の名前だと「人の便」に数えられ、**無人化の分母（自動の行）から外れる**。⚠️ 前方一致では入らない（`scheduler:<便名>` は人の便に落ちる）＝**1 語で完全一致**
- ⛔ **`run_end` を撃たずに終わらない。**開いたままの実行は分母から外れる＝走ったことが数えられない
- **帳簿に書かずに終わったら失敗**（旧「ログを書かずに終わったら失敗」の掟をそのまま移した）
- 便が何本あっても `seki` は `scheduler` 固定なので、**`run_last` では便ごとに引けない**（あれは席単位の口）。便ごとに見るのは §5 の窓＝上の tsv
